# RecallMap three-minute demo script

Target length: 2:50. Read only the English narration aloud. The Chinese text is a line-matched reference for rehearsal and is not part of the final video's running time.

## 0:00–0:15 — The hidden problem / 隐藏的问题

**Screen / 画面**

Open RecallMap on the start screen. Keep the product name, headline, and **Start sample lesson** button visible.

**English narration**

“Students can recognize a correct answer while carrying a wrong mental model. RecallMap makes that reasoning visible. Instead of giving another polished explanation, it asks the learner to teach the idea back, finds the missing link, and helps repair it.”

**中文对照**

“学生可能认得正确答案，却仍然保留着错误的思维模型。RecallMap 会把这种推理过程呈现出来。它不会直接再给一份精美答案，而是让学习者用自己的话讲解，找出缺失的推理环节，并帮助修复它。”

## 0:15–0:35 — Start without friction / 无门槛开始

**Screen / 画面**

Select **Start sample lesson** and show the built-in correlation-and-causation question.

**English narration**

“A judge can begin this built-in statistics lesson without an account or personal API key. The question asks why ice-cream sales and drowning incidents can rise together without one causing the other.”

**中文对照**

“评委无需注册账号，也不需要个人 API Key，就能开始这节内置的统计学课程。题目要求解释：为什么冰淇淋销量和溺水事件可能同时上升，但并不意味着其中一个导致了另一个。”

## 0:35–0:55 — Expose the reasoning / 暴露推理过程

**Screen / 画面**

Paste the prepared first explanation, then select **Reveal my blind spot**. End this clip immediately after the click.

**English narration**

“I’ll enter a plausible misconception: if two variables consistently move together, one probably causes the other unless the data has an error. RecallMap evaluates the reasoning against the supplied material, not the student’s polish or vocabulary.”

**中文对照**

“我会输入一个看起来很合理的误解：如果两个变量总是一起变化，那么其中一个很可能导致另一个，除非数据本身有错误。RecallMap 会依据给定材料检查推理，而不是评价学生的文采或词汇。”

## 0:55–1:30 — Reveal the priority gap / 找出关键断点

**Screen / 画面**

Cut to the completed reasoning map and briefly show `Live analysis — wait removed`. Point to the supported node, red priority gap, source evidence, and focused challenge.

**English narration**

“After the live analysis, the reasoning map separates supported links from the misconception. It preserves the association, then flags the causal leap as the priority gap. The source evidence says correlation does not identify the mechanism behind an association. RecallMap asks one focused question about hot weather affecting both outcomes, without revealing a complete answer.”

**中文对照**

“实时分析完成后，推理图会把有材料支持的环节与错误认识区分开来。它保留了‘两者相关’这一点，同时把直接跳到因果关系标记为最优先修复的断点。材料证据指出，相关性本身无法说明关联背后的机制。RecallMap 随后提出一个聚焦问题：炎热天气是否可能同时影响这两个结果，但它不会直接泄露完整答案。”

## 1:30–1:55 — Repair in the student's words / 用学生自己的话修复

**Screen / 画面**

Select **Work through this challenge**, paste the prepared revision, and select **Check my repaired understanding**.

**English narration**

“Now I answer in my own words. I identify temperature as a common cause and revise the explanation to include direct causation, reverse causation, selection bias, chance, and the need for additional evidence.”

**中文对照**

“现在我用自己的话回答。我把温度识别为一个共同原因，并修改解释，把直接因果、反向因果、选择偏差、随机性以及需要更多证据都考虑进去。”

## 1:55–2:20 — Make the change visible / 让理解变化可见

**Screen / 画面**

Cut to the completed result, briefly show `Live analysis — wait removed`, then pause on the green repaired node and the Before/After comparison.

**English narration**

“The repaired node turns green. The Before and After comparison shows exactly what changed: the original causal shortcut is replaced by several possible explanations and a requirement for evidence. RecallMap verifies a change in understanding instead of merely supplying the answer.”

**中文对照**

“修复后的节点变成绿色。前后对比清楚展示了发生的变化：原先草率的因果结论，被多个可能解释以及对额外证据的要求所取代。RecallMap 验证的是理解是否发生改变，而不是仅仅提供答案。”

## 2:20–2:40 — Technology and disclosure / 技术与披露

**Screen / 画面**

Show the public GitHub repository, the test folder, and the README provider disclosure. Do not show a local terminal, Azure portal, or credentials.

**English narration**

“The selected server provider performs the runtime analysis. The current public deployment uses Xiaomi MiMo V2.5 through an OpenAI-compatible Responses API. GPT-5.6 is supported through the OpenAI Responses API when `OPENAI_API_KEY` is configured, and OpenAI takes priority when both keys exist. Controlled non-demo MiMo production HTTP acceptance passed on 2026-07-18 with `fallback=false`. Codex was the development tool, not the runtime tutor. It helped research, design, implement, test, review, and deploy this project.”

**中文对照**

“运行时分析由服务器选择的模型提供方完成。当前公开部署通过兼容 OpenAI 的 Responses API 使用小米 MiMo V2.5。配置 `OPENAI_API_KEY` 后，代码也支持通过 OpenAI Responses API 使用 GPT-5.6；两个 Key 同时存在时优先使用 OpenAI。2026 年 7 月 18 日，非演示内容的 MiMo 生产 HTTP 验收已通过，且 `fallback=false`。Codex 是开发工具，而不是运行时导师。它帮助我完成了调研、设计、实现、测试、审查和部署。”

## 2:40–2:50 — Close / 收尾

**Screen / 画面**

Return to the repaired reasoning map and finish on the visible RecallMap brand.

**English narration**

“RecallMap does not replace thinking. It shows students where their reasoning breaks, then gives them a focused way to repair it.”

**中文对照**

“RecallMap 不会代替思考。它让学生看见自己的推理在哪里断裂，再提供一种聚焦的方法去修复它。”
