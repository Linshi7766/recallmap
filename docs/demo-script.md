# Recall three-minute demo script

Target length: 2:55–3:00. Spoken narration is approximately 307 words; bracketed cues are visual directions, not narration.

### 0:00–0:20 — The hidden problem

[Open Recall on the start screen.]

“Students can recognize a correct answer while still carrying the wrong mental model. Recall makes that hidden misunderstanding visible, then asks the student to repair it in their own words.”

### 0:20–0:40 — Start without friction

[Select **Start sample lesson**.]

“A judge can start this built-in statistics lesson without a Recall account or personal API key. The lesson asks why ice-cream sales and drowning incidents can move together without one causing the other.”

### 0:40–1:05 — Expose the reasoning

[Enter the tested first explanation and select **Reveal my blind spot**.]

“I’ll give a plausible misconception: if two variables consistently move together, one probably causes the other unless the data has an error. Recall does not reward polished wording. It examines the reasoning against the supplied material.”

### 1:05–1:38 — Reveal the gap with evidence

[Pause on the reasoning map and priority node. Point to the evidence.]

“The map preserves what is supported: the variables move together. It flags the direct causal leap as the priority misconception and shows the source evidence: ‘Correlation alone does not identify the mechanism that produced an association.’ It then asks one focused question about hot weather affecting both ice-cream sales and drownings. It does not reveal a complete answer.”

### 1:38–1:55 — Show resilient retry

[Use the prepared one-time diagnosis failure take, then select **Retry analysis**.]

“If analysis is temporarily unavailable, the exact student explanation stays on screen. Retry continues from the same work instead of asking the student to reconstruct it.”

### 1:55–2:23 — Repair in the student's words

[Select **Work through this challenge** and enter the tested revision.]

“Now I identify temperature as a common cause and revise the explanation to include reverse causation, confounding, selection bias, chance, and the need for additional evidence.”

### 2:23–2:40 — Make the change visible

[Select **Check my repaired understanding**. Show the green repaired node and Before/After card.]

“The priority node changes from misconception to supported, and the Before/After view shows the conceptual change. Recall verifies repaired reasoning; it does not merely supply an answer.”

### 2:40–2:55 — Explain the technology and disclosure

[Show the result, then briefly show the repository test/docs view.]

“At runtime, GPT-5.6 uses Responses API structured outputs for source-grounded diagnosis, the targeted challenge, and conceptual comparison. Codex researched, planned, implemented, and tested the project; it is not the runtime tutor. Normal demo requests are live. Only the exact scripted built-in path can use disclosed fixtures after an eligible live-model failure; pasted material never uses them.”

### 2:55–3:00 — Close

Recall doesn't replace thinking. It shows students where their thinking breaks—and helps them repair it.
